# 我给麦当劳的菜单做了次「体检」，发现活动推荐的新品一个都算不出热量

> 本文是我的 GitHub 项目介绍。比赛项目：[mcd-nutrition-optimizer](https://github.com/Hxxcb1412/mcd-nutrition-optimizer)，在线演示不用装：[点开就能玩](https://hxxcb1412.github.io/mcd-nutrition-optimizer/)

前几天刷到麦当劳 MCP 的活动日历接口，我顺手调了一下，然后发现一件挺有意思的事。

## 活动在推的新品，营养表里一个都没有

我用 `campaign-calendar` 拉了当月活动，定位出 7 个餐品名：

龙焰鸡腿堡、龙焰芝士棒鸡腿堡、马苏里拉拉丝芝士条、蓝莓爆爆珠麦旋风、灰焰圆筒、蘸酱炸鸡、鸡薯双全盒。

然后拿这 7 个名字去查 `list-nutrition-foods`——

**收录率 0%。一条都没有。**

麦当劳 10 月 9 日的活动推「龙焰鸡腿堡三件套 26.9 元起」，而它的营养数据在官方营养表里查不到。你点进去之前，没人能告诉你这顿多少钠。

## 整张菜单也一样

北京王府井新东安二号餐厅（storeCode 1950526），128 个在售餐品：

| 匹配方式 | 命中 | 覆盖率 |
|---|---|---|
| 精确同名 | 21 | 16.4% |
| 放宽到剥规格后缀 | 26 | 20.3% |
| 再放宽到括号归一化 | **27** | **21.1%** |
| 完全无数据 | **101** | 78.9% |

**覆盖率 21.1%。**

这不是接口坏了或者我调错了。营养表是季度更新的静态快照，门店菜单是实时数据，两者之间天然有时间差。

![数据缺口报告](https://hxxcb1412.github.io/mcd-nutrition-optimizer/data-gap-report.png)

## 我做的工具

既然有这问题，我写了个体检工具 `coverage_report.py`。它还专门标出**规格歧义**——菜单写「可乐」，营养表里有「可乐中杯/大杯/小杯」三条，钠含量不同。工具不静默取第一个，会把候选全列出来让你选杯型。

## 一个我没有做的功能

原本想加「用券后重算营养」。实测发现做不到：

`available-coupons` 返回的是一份 Markdown 图文列表，只有券名，没有 couponId、面额、有效期、适用商品。而营养重算必须知道券限制了哪些餐品。

拿不到这些就算价格和营养，只能靠猜。**猜出来的数字比不给更糟。**

所以改成了「券适用性检查」——用 `query-store-coupons` 返回的 `products[].productCode` 反查营养表，回答一个实际存在的问题：*这张券点了之后，能不能算清楚营养。*

## 三个真实 bug，都是数据抓出来才发现的

**1. 无糖可乐差点以「0 大卡 2mg 钠」成为最优解**

营养表里有 4 条记录的热量和蛋白质同时为 0。判据如果写成「四个字段全为 0」，无糖可乐的碳水是 **1** 不是 0，就会被当成真实数据参与计算——然后以「零热量」的身份赢下低卡推荐。

改成「热量与蛋白质同时为 0」才算对。

**2.「清淡午餐」收敛到三样饮品**

纯按钠排序时最优解是「冰美式 + 可乐 + 纯牛奶」——钠最低，但只有 8g 蛋白，本质上是三样饮料。

根因是低钠食物全在奶品类，而正餐类钠普遍 500-1000mg。改成「正餐优先 → 钠升序 → 热量升序」。

**3. 给 4 岁孩子推荐了汽水加牛奶**

这个我自己觉得挺离谱的。关键词表里「纯牛奶」含"牛"、「热浓浓抹茶牛奶」含"蛋"（浓**蛋**绿），都先命中了「蛋白」类，于是「可乐 + 纯牛奶」通过了「必须含主食或蛋白」的校验。

4 岁孩子的午餐，钠 73mg，蛋白 7g——数字全对，但不是儿童餐。

**成人场景下这只是荒谬，儿童场景是严重不当。** 现在儿童场景有独立的过滤规则。

## 现在做的事

- 你说「想吃得清淡点」，它翻译成「钠 ≤ 500mg、热量 ≤ 600kcal」，从 156 条有数据的餐品里算最优组合
- 孩子按 3-6 / 7-12 / 13-17 岁分段，阈值标明来自通用膳食参考值（非官方、非医疗建议）
- **下单前先告诉你哪些结论算不出来**，部分可信时拒绝输出部分和——漏掉的那项会让总热量被低估

## 全部数字都能复现

```
python scripts/smoke_test.py    # 24 项
python scripts/test_precheck.py # 58 项
```

204 项断言，不需要 MCP 连接，直接读实测抓取的数据。

**麦当劳的菜单设计本来就不是低钠餐，这不是麦当劳的问题。** 我只是想把数据边界说清楚，让使用者知道自己能算什么、不能算什么。

估一个数字填上去很容易，但那不是解决问题，是把问题藏起来。
